 1. Project Title Retrieval-Augmented Vision AI Assistant for Image Analytics (Using a Custom-Trained CNN Image Encoder and FAISS Vector Search) 2. Abstract The proposed system is an artificial intelligence based image analytics assistant that lets a user search a collection of images either by uploading a sample photo or by typing a short text query, and receive both the most relevant matching images and a plain-language explanation of what was found. Instead of relying on a pretrained or third-party vision API, the system&apos;s image-vectorization component is a convolutional neural network (CNN) trained entirely from scratch by the project team on the CIFAR-100 dataset, which converts every image into a fixed-length numerical vector (embedding). These vectors are stored in a FAISS vector index, which allows near-instant similarity search across the image collection using cosine similarity. A lightweight local text-encoder (MiniLM) allows typed queries to be matched against each image&apos;s predicted content, and a locally hosted language model (TinyLlama) reasons over the retrieved results to generate a grounded natural-language answer, referencing specific results rather than guessing. The complete pipeline - dataset preparation, CNN training, embedding extraction, vector indexing, retrieval, and answer generation - runs without any paid API and without an internet connection once the models are in place. The system can be pointed at any image domain (medical, industrial, agricultural, retail, etc.) by simply changing the image folder, making it a reusable and explainable foundation for AI-based image analytics. 3. Introduction Image collections are growing rapidly across almost every domain - hospitals store thousands of scans, factories photograph products and defects, farms capture drone and field images, and retailers catalog product photos. Manually browsing such collections to answer a specific question (&quot;find images similar to this one&quot; or &quot;which images show a particular condition&quot;) is slow and does not scale. Traditional approaches rely on either manual tagging and keyword search, which misses visual similarity entirely, or a trained classifier, which can only answer the one fixed question it was trained for and must be retrained for every new question. Pretrained cloud vision APIs can help, but they require continuous internet access, incur cost per call, and may not be acceptable for privacy-sensitive images. The proposed project, a Retrieval-Augmented Vision AI Assistant, addresses this by combining three components into a single offline pipeline: a CNN trained from scratch to convert images into vectors, a FAISS index for fast similarity search over those vectors, and a local language model that explains the retrieved results in plain language. This mirrors the &quot;Retrieval-Augmented Generation&quot; (RAG) approach widely used for text-based AI assistants, applied here to images. Because the embedding model is trained by the project team rather than downloaded as a finished pretrained network, the project also demonstrates the complete machine learning lifecycle: dataset preparation, model design, training and evaluation, deployment, and integration into a working application. 4. Problem Statement Current approaches to searching and understanding image collections face the following problems: Keyword or filename-based search cannot find images based on visual content or similarity. Trained classifiers answer only one predefined question and cannot generalize to new, open-ended queries. Commercial vision APIs require continuous internet access, incur per-call cost, and raise data-privacy concerns for sensitive images. Pretrained embedding models (e.g., off-the-shelf CLIP checkpoints) are convenient but give no insight into how the vectorization model was trained or why it works. Search tools typically return only a ranked list of images with no explanation of why they were considered relevant. There is no single, reproducible, fully offline pipeline that combines a self-trained feature extractor, vector search, and natural-language explanation. Manually reviewing large image collections to find similar or relevant items does not scale as the collection grows. Therefore, an intelligent, explainable, and fully offline image-retrieval assistant is required - one that is built on a model the project team trained and understands end-to-end, rather than a pretrained black box. 5. Working Methodology Step 1 - Dataset Preparation CIFAR-100 is used to train the embedding model: 60,000 images across 100 general-purpose classes (50,000 for training, 10,000 for testing). Images are resized to 64x64, normalized, and augmented with random horizontal flips during training to improve generalization. Step 2 - CNN Architecture Design The network (EmbeddingCNN) has a feature extractor of four convolutional blocks (Conv2D, BatchNorm, ReLU, MaxPool), followed by an embedding layer that compresses the final feature map into a 256-number vector, followed by a classifier head used only during training. The full network has approximately 2.04 million trainable parameters. Step 3 - Model Training The model is trained using the Adam optimizer, cross-entropy loss, and a step learning-rate scheduler, for 15 epochs with a batch size of 128, on a Google Colab GPU (T4) runtime. During training, the best-performing checkpoint (by test accuracy) is saved automatically. Step 4 - Model Evaluation Training loss and test accuracy are tracked after every epoch and plotted as curves. The embedding space is further validated using t-SNE, a dimensionality-reduction technique that projects the 256-dimension vectors into 2D so that clustering by class can be visually inspected. Step 5 - Embedding Extraction and Indexing The trained CNN is used to convert every image in a target image collection into a 256-dimension vector and a predicted class label. Vectors are normalized and stored in a FAISS IndexFlatIP (cosine-similarity) index. A local MiniLM text encoder separately encodes each predicted label into a second FAISS text index, enabling text-based queries. Step 6 - Query Processing An uploaded image query is passed through the same trained CNN used for indexing, producing a query vector. A typed text query is passed through the local MiniLM text encoder instead. Step 7 - Retrieval FAISS compares the query vector against all indexed vectors and returns the top-k nearest results by cosine similarity, along with each result&apos;s filename, predicted label, confidence, and similarity score. Step 8 - Answer Generation The retrieved results&apos; metadata is formatted into a prompt and passed to a locally hosted TinyLlama-1.1B-Chat model (loaded once and cached for speed). The model is instructed to answer only from the given information, reference specific result numbers, and state clearly when the evidence is insufficient, reducing the risk of hallucinated claims. Step 9 - Dashboard Presentation A Streamlit web application displays the query (image or text), a thumbnail grid of the retrieved results with filenames, predicted labels and similarity scores, and the generated explanation beneath them. Step 10 - Documentation and Reporting Training configuration and results are saved to a JSON report, and a complete Google Colab notebook records dataset visualization, training curves, the embedding-vector output for a test image, the t-SNE cluster plot, and a live similarity-search demonstration - providing a full, reproducible record for evaluation. 11. The CNN is trained from scratch so the project demonstrates real model ownership rather than reusing a pretrained black box. FAISS is used because it is purpose-built for extremely fast nearest-neighbour search, even as the image collection grows. MiniLM is used only for lightweight local text-to-text matching, keeping the text-query path fully offline. TinyLlama is used because it is small enough to run on ordinary laptop hardware while still following chat-style instructions well enough to produce grounded, readable explanations. 12. Advantages Provides semantic, visual-similarity image search instead of only filename or keyword search. Uses a self-trained model, giving full transparency and ownership of the vectorization process. Runs entirely offline after training and indexing, avoiding API cost and data-privacy concerns. Supports both image and text queries within the same system. Produces a natural-language explanation rather than only raw ranked results. Scales efficiently to larger image collections through FAISS. Modular design allows the encoder, retriever, or generator to be upgraded independently. Suitable for privacy-sensitive domains (medical, enterprise, defense) where sending images to external APIs is undesirable. 15. Future Scope 1. Domain-Specific Fine-Tuning - retrain or fine-tune the CNN on a domain-specific labeled dataset (e.g., medical or agricultural images) for stronger relevance. 2. Metric-Learning Objective - replace the classification loss with a triplet or contrastive loss to directly optimize similarity rather than classification accuracy. 3. Approximate Nearest-Neighbour Indexing - use FAISS IVF or HNSW indexes to scale to much larger image collections. 4. Joint Vision-Language Embedding - train or fine-tune a model to embed images and text into the same space (CLIP-style) for true semantic text search. 5. Larger Local Language Model - upgrade from TinyLlama to a larger locally hosted model, hardware permitting, for richer explanations. 6. Mobile or Edge Deployment - optimize the trained CNN (quantization or pruning) for on-device inference. 7. User Feedback Loop - let users mark results as relevant or irrelevant to improve future ranking. 8. Multi-Image Query - allow multiple reference images as a single query for more robust matching. 9. Explainable Retrieval - highlight which regions of an image contributed most to its embedding (e.g., Grad-CAM). 10. Video Support - extend the pipeline with key-frame extraction for video similarity search.
